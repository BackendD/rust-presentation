Rust Advanced

ورود به بخش مفاهیم پیشرفته: مدیریت خطا، پکیج منیجر Cargo، تریت‌ها، جنریک‌ها، همزمانی و کد ناایمن.
مدیریت خطا (Error Handling)
  • Result<T, E> — برای خطاهای قابل بازیابی
  • Option<T> — برای مقادیر اختیاری
  • عملگر ? — انتشار خطا به caller
  • panic! — برای خطاهای غیرقابل بازیابی
  • بدون exception — همه چیز صریح است
fn divide(a: f64, b: f64)
    -> Result<f64, String>
{
    if b == 0.0 {
        Err(String::from("تقسیم بر صفر"))
    } else {
        Ok(a / b)
    }
}

fn main() -> Result<(),
    Box<dyn std::error::Error>>
{
    let res = divide(10.0, 2.0)?;
    println!("نتیجه: {}", res);
    Ok(())
}
مدیریت خطای صریح با Result و Option؛ عدم وجود null و exception سنتی، و کارایی عملگر علامت سوال.

Trait ها
Trait مجموعه‌ای از متدها را تعریف می‌کند که تایپ‌ها باید پیاده‌سازی کنند — شبیه interface. 
trait Animal {
    fn name(&self) -> &str;
    fn speak(&self) -> String;
    fn description(&self) -> String { // متد پیش‌فرض
        format!("{} می‌گوید: {}", self.name(), self.speak())
    }
}

struct Dog;
impl Animal for Dog {
    fn name(&self) -> &str { "سگ" }
    fn speak(&self) -> String { String::from("هاو هاو") }
}

fn make_sound(a: &dyn Animal) {  // trait object
    println!("{}", a.description());
}

fn main() {
    let dog = Dog;
    make_sound(&dog); // سگ می‌گوید: هاو هاو
}
تریت‌ها به عنوان قراردادهای رفتاری در راست؛ نقش آن‌ها به جای رابط‌ها (interfaces) و پیاده‌سازی متدهای پیش‌فرض.
جنریک‌ها (Generics)
جنریک‌ها بدون هزینه زمان اجرا — کامپایلر برای هر تایپ کد اختصاصی تولید می‌کند (monomorphization). 
// تابع جنریک با قید Trait
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in list {
        if item > max { max = item; }
    }
    max
}

// ساختار جنریک
struct Pair<T> {
    first: T,
    second: T,
}

impl<T: std::fmt::Display> Pair<T> {
    fn show(&self) {
        println!("({}, {})", self.first, self.second);
    }
}

fn main() {
    let nums = vec![34, 50, 25, 100, 65];
    println!("بزرگترین: {}", largest(&nums));
}
جنریک‌ها برای انتزاع نوع بدون افت کارایی با تکیه بر Monomorphization در زمان کامپایل (Zero-cost abstraction).
بستارها (Closures)
Closure توابع ناشناسی هستند که می‌توانند متغیرهای محیط اطراف خود را capture کنند. 
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(x)
}

fn main() {
    let factor = 3;
    let multiply = |n| n * factor; // capture by reference

    println!("{}", apply(multiply, 5)); // 15

    // تبدیل با iterator + closure
    let nums = vec![1, 2, 3, 4, 5];
    let evens: Vec<i32> = nums.iter()
        .filter(|&&x| x % 2 == 0)
        .map(|&x| x * x)
        .collect();
    println!("{:?}", evens); // [4, 16]
}

// سه نوع Closure Trait:
// Fn     — capture by reference (چندین بار قابل فراخوانی)
// FnMut  — capture by mutable reference
// FnOnce — capture by value (یک بار قابل فراخوانی)
کلوزرهای راست و سه تریت Fn، FnMut و FnOnce برای مدیریت نحوه کپچر متغیرها از محیط اطراف.
همزمانی (Concurrency)
Rust با ضمانت‌های کامپایلی از data race جلوگیری می‌کند — fearless concurrency. 
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let c = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            *c.lock().unwrap() += 1;
        }));
    }
    for h in handles { h.join().unwrap(); }
    println!("نتیجه: {}", *counter.lock().unwrap()); // 10
}

// channel برای ارسال پیام بین thread‌ها
use std::sync::mpsc;
let (tx, rx) = mpsc::channel();
thread::spawn(move || { tx.send("سلام").unwrap(); });
println!("{}", rx.recv().unwrap());
همزمانی بدون ترس (Fearless Concurrency)؛ استفاده از Arc و Mutex به همراه چک‌های کامپایلر Send و Sync.
برنامه‌نویسی ناهمزمان (Async / Await)
async/await برنامه‌نویسی ناهمزمان را به سبک sync می‌نویسد. Tokio پرکاربردترین async runtime است. 
use std::time::Duration;
use tokio::time::sleep;

#[tokio::main]
async fn main() {
    let result = fetch_data().await;
    println!("{}", result);
    
    // اجرای موازی چند Future
    let (a, b) = tokio::join!(
        fetch_data(),
        fetch_data()
    );
    println!("{} — {}", a, b);
}

async fn fetch_data() -> String {
    sleep(Duration::from_millis(100)).await;
    String::from("داده دریافت شد")
}
برنامه‌نویسی ناهمزمان و مدل غیرفعال (lazy) در راست با تکیه بر فیوچرها و رانتایم قدرتمند Tokio.
Pin<P>
Pin<P> تضمین می‌کند که مقداری که pointer به آن اشاره می‌کند در حافظه جابه‌جا نمی‌شود. این برای self-referential structure‌ها در async/await ضروری است.
  • Unpin — تایپ‌هایی که جابه‌جایی آن‌ها ایمن است (اکثر تایپ‌ها)
  • !Unpin — تایپ‌هایی که نباید جابه‌جا شوند (مثل Futureهای پیچیده)
  • Pin::new() — برای تایپ‌های Unpin
  • Box::pin() — برای pin کردن روی heap
use std::pin::Pin;
// async fn خودکار Future ای تولید می‌کند که !Unpin است
// executor باید آن را pin کند قبل از poll
async fn example() { /* ... */ }
let fut = Box::pin(example());
مفهوم Pinning برای جلوگیری از جابه‌جایی مقادیر خودارجاع‌دهنده در حافظه که در استیت‌ماشین‌های async الزامی است.
ماکروها (Macros)

ماکروهای اعلانی (macro_rules!)

macro_rules! say_hello {
    () => {
        println!("سلام Rust!");
    };
    ($name:expr) => {
        println!("سلام {}!", $name);
    };
}

say_hello!();          // سلام Rust!
say_hello!("دنیا");   // سلام دنیا!

ماکروهای رویه‌ای (Procedural)

  • #[derive(...)] — تولید خودکار کد
  • derive(Debug, Clone, Serialize)
  • Attribute macros — تغییر آیتم
  • Function-like macros — مثل vec![]
#[derive(Debug, Clone)]
struct Point {
    x: f64,
    y: f64,
}
let p = Point { x:1.0, y:2.0 };
println!("{:?}", p);
سیستم متامارکتینگ راست: تفاوت ماکروهای اعلانی (macro_rules!) با ماکروهای رویه‌ای (Procedural Macros).
کد ناایمن (Unsafe)
unsafe مسئولیت ایمنی حافظه را به برنامه‌نویس می‌سپارد — با احتیاط استفاده کنید.

در unsafe می‌توانید:

  • dereference raw pointer
  • فراخوانی تابع unsafe
  • دسترسی/تغییر متغیر static قابل تغییر
  • پیاده‌سازی unsafe trait
  • دسترسی به فیلد union
fn main() {
    let mut num = 5;
    // raw pointer ساختن
    let r1 = &num as *const i32;
    let r2 = &mut num as *mut i32;

    unsafe {
        println!("r1: {}", *r1);
        *r2 = 10;
        println!("r2: {}", *r2);
    }
}

unsafe fn dangerous() {
    println!("این تابع ناایمن است");
}
مرز ایمنی راست: ۵ قدرت خاص در بلاک unsafe و مسئولیت خطیر توسعه‌دهنده در حفظ تغییرناپذیرهای حافظه.
رابط توابع خارجی (FFI)
FFI امکان فراخوانی کد C از Rust و بالعکس را فراهم می‌کند. 
// فراخوانی C از Rust
extern "C" {
    fn abs(x: i32) -> i32;
    fn strlen(s: *const i8) -> usize;
}

fn main() {
    unsafe {
        println!("abs(-5) = {}", abs(-5));
    }
}

// صادر کردن به C
#[no_mangle]
pub extern "C" fn add(a: i32, b: i32) -> i32 {
    a + b
}
  • cbindgen — تولید header C از Rust
  • bindgen — تولید binding Rust از C header
  • استفاده در: kernel modules، WebAssembly، Python extensions
  • ابزار cargo build --release → کتابخانه .so / .dll
تعامل دوطرفه با کتابخانه‌های زبان C بدون سرریز کارایی و امکان استفاده از راست در سیستم‌های قدیمی.
شی‌گرایی در Rust
Rust به‌طور کامل شی‌گرا نیست اما از بسیاری مفاهیم آن پشتیبانی می‌کند.
  • ✅ Encapsulation — با pub/private و module
  • ⚠️ Inheritance — پشتیبانی ندارد، جایگزین: Trait
  • ✅ Polymorphism — با Generics و Trait object
  • ✅ Methods — با impl بلوک‌ها
در Rust نگاه ترکیب (Composition) بر وراثت ارجحیت دارد.
راست چگونه بدون وراثت سنتی، اصول شی‌گرایی (کپسوله‌سازی و چندریختی) را با ترکیب struct و trait پیاده می‌کند.
ساختار به‌عنوان شی (struct + impl)
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    // سازنده (constructor)
    pub fn new(width: f64, height: f64) -> Self {
        Rectangle { width, height }
    }

    // متد نمونه
    pub fn area(&self) -> f64 {
        self.width * self.height
    }

    pub fn perimeter(&self) -> f64 {
        2.0 * (self.width + self.height)
    }

    pub fn is_square(&self) -> bool {
        self.width == self.height
    }
}

fn main() {
    let rect = Rectangle::new(10.0, 5.0);
    println!("مساحت: {}", rect.area());
    println!("محیط: {}", rect.perimeter());
}
تعریف شی در راست: تجمیع داده‌ها در struct و انتساب رفتارها از طریق بلاک‌های impl.
کپسوله‌سازی (Encapsulation)
  • pub — قابل دسترسی از همه جا
  • بدون pub — خصوصی به ماژول
  • pub(crate) — فقط داخل کتابخانه
  • pub(super) — فقط ماژول پدر
  • ماژول‌ها مرز کپسوله‌سازی هستند
mod bank {
    pub struct Account {
        owner: String, // خصوصی
        balance: f64,  // خصوصی
    }

    impl Account {
        pub fn new(owner: &str) -> Self {
            Account {
                owner: owner.to_string(),
                balance: 0.0,
            }
        }
        pub fn deposit(&mut self, amount: f64) {
            if amount > 0.0 {
                self.balance += amount;
            }
        }
        pub fn balance(&self) -> f64 {
            self.balance
        }
    }
}

use bank::Account;
let mut acc = Account::new("علی");
acc.deposit(1000.0);
println!("{}", acc.balance()); // ✅
// acc.balance = 999.0; // ❌ خطا
کپسوله‌سازی با کلیدواژه pub در سطح ماژول‌ها؛ فیلدهای مخفی و تضمین یکپارچگی حالت درونی اشیاء.
# وراثت را پشتیبانی نمی‌کند ### دلایل استفاده از وراثت - استفاده مجدد از کد - پولیمورفیسم (چندریختی)
چرایی عدم پشتیبانی از وراثت کلاسیک؛ ترجیح ترکیب بر وراثت و حل نیازها با traitها و trait objectها.
استفاده مجدد از کد — Default Trait Methods
جایگزین وراثت در Rust: پیاده‌سازی پیش‌فرض در Trait 
trait Greet {
    fn name(&self) -> &str;
    // متد پیش‌فرض — نیاز به override ندارد
    fn greeting(&self) -> String {
        format!("سلام، {}!", self.name())
    }
}

struct Person { name: String }
impl Greet for Person {
    fn name(&self) -> &str { &self.name }
    // greeting() از پیش‌فرض استفاده می‌کند
}

struct Robot { id: u32 }
impl Greet for Robot {
    fn name(&self) -> &str { "ربات" }
    fn greeting(&self) -> String { // override
        format!("BEEP BOOP — Robot #{}", self.id)
    }
}

fn main() {
    let p = Person { name: "علی".to_string() };
    let r = Robot { id: 42 };
    println!("{}", p.greeting()); // سلام، علی!
    println!("{}", r.greeting()); // BEEP BOOP — Robot #42
}
استفاده مجدد از کد از طریق پیاده‌سازی پیش‌فرض متدها در تریت‌ها و امکان بازنویسی در صورت نیاز.
پولیمورفیسم (Polymorphism)

جایگذینی آبجکت‌ها به‌جای یکدیگر در زمان اجرا چنانچه مشترکا ویژگی خاصی دارند.

Static dispatch (Generic): بدون هزینه زمان اجرا

fn print_area<T: Shape>(s: &T) {
    println!("{}", s.area());
}

Dynamic dispatch (dyn Trait): vtable در زمان اجرا

fn print_area(s: &dyn Shape) {
    println!("{}", s.area());
}

let shapes: Vec<Box<dyn Shape>> = vec![
    Box::new(Circle { r: 1.0 }),
    Box::new(Rect { w: 2.0, h: 3.0 }),
];
for s in &shapes { print_area(s.as_ref()); }
چندریختی ایستا با جنریک‌ها (بدون هزینه زمان اجرا) در برابر چندریختی پویا با dyn Trait (vtable).
